# Программная реализация кэша (Cache Architecture)

## Функции

Интерфейс модуля кэширования разделен на четыре логические группы функций:

### 1. Базовые операции (CRUD)
* **`set(key, value, [ttl])` / `put(key, value)`** — Запись данных в кэш. Принимает ключ, значение и опциональный параметр `ttl` (Time To Live) — время жизни записи в секундах или миллисекундах.
* **`get(key)`** — Чтение из кэша. Возвращает значение по ключу. Если ключ отсутствует или его срок действия истек, возвращает пустой ответ (`null`/`None`) или генерирует исключение.
* **`delete(key)` / `evict(key)`** — Удаление элемента. Принудительно стирает запись по указанному ключу.
* **`has(key)` / `exists(key)`** — Проверка наличия ключа. Возвращает булево значение. Перед ответом проверяет актуальность данных (не истек ли TTL).

### 2. Управление размером и стратегии вытеснения (Eviction Policies)
При достижении лимита памяти (`max_size`) кэш автоматически освобождает место, используя одну из функций вытеснения:
* **`evict_el()`** — метод, отвечающий за освобождение памяти при переполнении кэша.
* **`clear()` / `flush()`** — Полная очистка. Мгновенно стирает все данные и освобождает выделенную память.

### 3. Контроль времени жизни данных
* **`check_expired()` / `cleanup()`** — Функция инвалидации устаревших данных. Может работать в двух режимах:
  * **Ленивое удаление (Lazy Expiration):** проверка и удаление происходят прямо внутри `get()` при попытке чтения.
  * **Фоновое удаление (Background Cleaner):** очистка запускается периодически по таймеру в отдельном потоке.

### 4. Метрики и мониторинг
* **`size()` / `count()`** — Возвращает текущее количество активных записей в кэше.
* **`get_stats()`** — Предоставляет метрики эффективности работы:
  * **Cache Hit** — количество успешных чтений из кэша.
  * **Cache Miss** — количество запросов, в ходе которых данных в кэше не оказалось.
  * **Hit Ratio** — процентное отношение попаданий к общему числу запросов (главный метрика эффективности).
